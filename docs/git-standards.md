# Git Standards

## Commit Messages
Follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <short summary>
```

Examples:
- `feat(terraform): initialize AWS provider and project structure`
- `fix(network): correct subnet CIDR overlap`
- `docs(adr): add ADR-001 for Terraform decision`

Common types: `feat`, `fix`, `docs`, `refactor`, `chore`, `test`.

## Branching
- `main` is the primary branch; keep it in a working, pushable state.
- Prefer short-lived feature branches for larger changes, merged via PR when
  collaborating with others.

## What Never Gets Committed
- `.terraform/` (provider binaries — can be 100s of MB, regenerated by
  `terraform init`)
- `*.tfstate`, `*.tfstate.*` (local state, may contain secrets)
- `*.tfvars` (often holds environment-specific or sensitive values)

These are enforced via `.gitignore`. If a large binary or state file is
accidentally staged, remove it with `git rm --cached <path>` before
committing — GitHub rejects any file over 100 MB, and rejection happens at
push time for the whole set of new commits, not just the tip.

## Before Pushing
- Run `git status` to confirm only intended files are staged.
- If a commit hasn't been pushed successfully yet, it's safe to
  `git commit --amend` to fix mistakes (e.g. drop an accidentally committed
  large file) rather than stacking a corrective commit on top.
- Once a commit is on the shared remote, avoid rewriting history
  (`amend`, `rebase`, `push --force`) without coordinating with collaborators.
